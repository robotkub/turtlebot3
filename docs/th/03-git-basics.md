# 3. Git พื้นฐาน

## Git คืออะไร ทำไมต้องใช้

Git เก็บ "ประวัติ" ของโค้ดทุกครั้งที่เซฟ (commit) ทำให้:
- ย้อนกลับไปดูโค้ดเวอร์ชันเก่าได้ ถ้าแก้พังก็ย้อนกลับได้ ไม่ต้องกลัวเสียของ
- ทีมหลายคนแก้โค้ดพร้อมกันได้โดยไม่เขียนทับกัน
- เห็นว่าใครแก้อะไร ตอนไหน ทำไม

**GitHub** คือเว็บที่เก็บโค้ดของเรา (`https://github.com/robotkub/turtlebot3`)
ทุกคนในทีม pull โค้ดล่าสุดจากตรงนี้ และ push โค้ดที่แก้กลับขึ้นไป

## คำสั่งที่ใช้บ่อย

| คำสั่ง | ใช้ทำอะไร |
|---|---|
| `git clone <url>` | ดาวน์โหลด repo มาไว้ในเครื่อง (ทำครั้งเดียวตอนเริ่ม) |
| `git status` | ดูว่าแก้ไฟล์อะไรไปบ้าง ยังไม่ได้ commit |
| `git pull` | ดึงโค้ดล่าสุดจาก GitHub มาอัปเดตเครื่องตัวเอง |
| `git add <file>` | บอก git ว่าจะเอาไฟล์นี้ไป commit ด้วย |
| `git commit -m "ข้อความ"` | เซฟ snapshot ของโค้ด พร้อมข้อความอธิบายว่าทำไมแก้ |
| `git push` | ส่ง commit ที่ทำไว้ขึ้น GitHub ให้คนอื่นเห็นด้วย |
| `git log --oneline` | ดูประวัติ commit ทั้งหมดแบบสั้นๆ |

## Workflow ที่ทีมนี้ใช้

**ก่อนเริ่มแก้โค้ดทุกครั้ง** -- pull ให้ล่าสุดก่อนเสมอ กันโค้ดชนกับที่เพื่อนแก้ไปแล้ว:

```bash
cd ~/turtlebot3_ws
git pull
```

**แก้โค้ดเสร็จแล้ว อยากเซฟ**:

```bash
git status                          # ดูก่อนว่าแก้อะไรไปบ้าง
git add src/ttb3_mission/ttb3_mission/mission_manager.py   # เลือกไฟล์ที่จะ commit
git commit -m "อธิบายสั้นๆ ว่าทำไมแก้ ไม่ใช่แก้อะไร"
git push
```

## ตัวอย่างข้อความ commit ที่ดี

เขียนว่า **ทำไมถึงแก้** ไม่ใช่ **แก้อะไร** (โค้ดมันบอกอยู่แล้วว่าแก้อะไร):

- ดี: `fix: ปรับ approach_close_size ให้ใกล้ victim sign มากขึ้นก่อนดีดกล่อง`
- ไม่ดี: `แก้โค้ด`, `update`, `test`

## ติดปัญหาเวลา push แล้วโดน reject

ถ้า `git push` ขึ้น error ว่า "rejected" หรือ "non-fast-forward" แปลว่ามีคน push
ก่อนหน้าคุณ (โค้ดใน GitHub ใหม่กว่าของคุณ) แก้ด้วย `git pull` ก่อน แล้วค่อย push ใหม่:

```bash
git pull
git push
```

ถ้า pull แล้วมีไฟล์ที่ทั้งสองฝั่งแก้ตรงกัน (merge conflict) -- git จะทำเครื่องหมาย
`<<<<<<<` / `=======` / `>>>>>>>` ในไฟล์ที่ชนกัน เปิดไฟล์นั้นแก้เอง เลือกว่าจะเก็บ
บรรทัดไหน ลบเครื่องหมายพวกนี้ออก แล้ว `git add` + `git commit` ต่อได้เลย

**อย่าใช้** `git push --force` หรือ `git reset --hard` โดยไม่ถามทีมก่อน --
คำสั่งพวกนี้ลบงานคนอื่นทิ้งได้แบบกู้คืนยาก
